## Design Specificity Verdict

**Start here.** Largely product-anchored, with one glaring generic hole. Browse, detail, reader, library, upload, admin, creator-apply all encode the comic domain (komik branding, cover-first grid, chapter lists, resume, apply-to-publish gating) and follow DESIGN.md tokens precisely. **Exception:** `dashboard/+page.svelte:23-27` is category-interchangeable scaffolding — `<h1>Dashboard</h1>`, `<p>Welcome {name}</p>`, `<p>API: {message}</p>`, bare `Loading...`/`Redirecting to login...`. Zero design-system tokens, no type scale, no layout. A boilerplate artifact that survived into the surface.

**Deterministic scan (Assessment B):** `detect.mjs` ran DEGRADED — HTML parser modules (htmlparser2/css-select/css-tree/domutils) are not installed, so it fell back to regex and could NOT evaluate computed contrast or selector matching. Findings are an undercount. Two hits, both false positives for this system:
- `overused-font` on Fraunces (app.css:6) — deliberate editorial choice in DESIGN.md, not slop.
- `broken-image` on the reader's dynamic `<img>` (read/[chapterId]:20) — built per-page from page manifest, not a literal empty src.

**Manual a11y cross-check (parent, source-level):**
- `#a4a09e` decorative: used ONLY as `placeholder:text-decor` and `disabled:text-decor` — never as body text on cream. ✅ Matches DESIGN.md "never text on cream" rule. No violation.
- Alt text: `ComicCard:31` + detail cover `:354` have `alt={title}` ✅. BUT `library:42` and `read/[chapterId]:230` use `alt=""`. The reader page image is the actual comic content — `alt=""` strips it from AT. ⚠️ Minor a11y gap (Sam).
- Focus: `focus-visible:ring-2 ring-accent/60` on buttons, `focus-visible:border-accent` on inputs/selects ✅. Browse search/genre use `focus:border-accent` (fine).
- ARIA: header nav `aria-label="main"` ✅, LocaleSwitcher `aria-label` ✅, reader pager `aria-label` ✅.

## Overall Impression
A genuinely well-built editorial comic reader with one broken first-impression surface (dashboard) and two real interaction defects (invisible auth errors, click-to-advance reader trap). The reading experience is the strongest, most on-brand part. Single biggest opportunity: make auth failures visible and fix the reader's input model.

## What's Working
1. **Reader immersion** (read/[chapterId]): chrome stripped, dark theme swap (Reader-Swap rule), resume-to-last-page, throttled progress flush. Best-built surface.
2. **Editorial consistency** (app.css, Header, ComicCard): One-Voice crimson, flat hairlines, Fraunces eyebrow+diamond, `komi**k**` wordmark — coheres to DESIGN.md to the token.
3. **Server-truth mutation model** (comic/[slug]:22-100): optimistic toggle → revert on catch → invalidate() re-runs load. Fewer stale states than typical client caches.

## Priority Issues

- **[P0] Auth errors invisible.** SignInForm:24 / SignUpForm:31 `onError` only `console.log`. Wrong password → silent. Violates Nielsen 1 & 10. *Fix:* render a visible `role="alert"` (TanStack Form error state or local state), like every other form does. *Suggested command:* `$impeccable clarify` (error copy) then `$impeccable harden`.
- **[P0] Reader click-anywhere-advances is a trap.** read/[chapterId]:189 `<svelte:window onclick={e => e.target===document.body && advance()}>` + each page `div role="img" onclick={advance}` (:222). Tapping the comic skips forward; no click-to-go-back; on touch every tap advances. `role="img"` + click has no keyboard handler → not operable by Sam. *Fix:* drop window body-click; make reading scroll/keyboard-driven; add explicit Prev/Next + page-jump input; reserve click for zoom/panel-view. *Suggested command:* `$impeccable adapt`.
- **[P1] `dashboard/+page.svelte` is a generic stub.** :23-27 bare headings, no tokens/layout/nav. First screen after sign-up is "Dashboard / Welcome / API:". Violates heuristic 4 + design-specificity. *Fix:* build a real, role-gated dashboard in the design system (font-display, eyebrow, surface panels) or repoint the route. *Suggested command:* `$impeccable shape` / `$impeccable document`-followed-by-build.
- **[P2] Error surfaces inconsistent + over-generic.** Detail save/follow errors use plain `text-accent` spans (:437,:453 have `role="alert"`; edit/delete :271,:339 don't); most catch blocks collapse to `m.error_generic()`. *Fix:* standardize all to Input/Textarea pattern (`role="alert"`, crimson) and pass specific mapped messages from `mapWriteError`. *Suggested command:* `$impeccable clarify` + `$impeccable harden`.
- **[P3] Reader working-memory gap.** No thumbnail rail / TOC / jump input; 0.5px bar easy to miss (read:202,:206). In a 40-page chapter, position recall is hard. *Fix:* add a page-list or jump input and make progress more salient. *Suggested command:* `$impeccable layout`.

## Persona Red Flags
- **Sam (a11y-dependent):** reader `div role="img" onclick` (:220,:222) announced as image, not button, no keyboard path; window body-click advances. No skip link; dashboard unstyled. Cannot navigate reader by keyboard/AT.
- **Jordan (first-timer):** account creation lands on bare `Dashboard / API:` stub; login error invisible (P0). First impression reads as broken.
- **Casey (mobile):** reader click-to-advance catastrophic on touch — every tap skips a page. Worst mobile failure on the surface.

## Questions to Consider
1. Is reader click-to-advance a feature or an accident — should reading be scroll-driven with click reserved for zoom/panel-view, matching how people actually consume digital comics?
2. Why does sign-up end on a bare "Dashboard / API:" stub — is `/dashboard` a real destination or a dead route to cut/replace with a guided first-read?
3. The 12-genre multi-select and admin ID-paste workflows assume power users — is there a lighter Jordan-path to discover and publish without taxonomy/ID friction?
